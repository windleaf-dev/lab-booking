# 接口说明（第三阶段）

- 基础地址：`http://127.0.0.1:8091/api`
- 除登录和健康检查外，所有接口需要请求头：

```http
Authorization: Bearer <token>
```

- 统一响应结构：

```json
{
  "code": 200,
  "message": "ok",
  "data": {}
}
```

- 业务失败时 `code` 与 HTTP 状态码一致（400 / 401 / 403 / 404 / 500），`message` 为中文提示。
- 日期格式：`yyyy-MM-dd`；时间字段：`HH:mm:ss`；日期时间：`yyyy-MM-ddTHH:mm:ss`。

### 角色与权限

| 角色 | 说明 |
| --- | --- |
| `ADMIN` | 管理员，全部功能 + 用户管理 |
| `TEACHER` | 教师，设备 / 分类维护 + 审批 |
| `STUDENT` | 学生，预约 / 签到 / 查看统计 |

### 2.1 登录

```json

```

| 场景 | HTTP | message |
| --- | --- | --- |
| 参数为空 | 400 | 请输入用户名和密码 |
| 账号或密码错误 | 401 | 用户名或密码错误 |
| 账号被禁用 | 403 | 该账号已被禁用 |

### 2.2 当前用户

`GET /auth/me`

```json

  "code": 200,
  "message": "ok",
  "data": {

    "username": "admin",
    "realName": "系统管理员",
    "role": "ADMIN"
  }

```

### 2.3 修改密码

`POST /auth/password`

```json
{ "oldPassword": "123456", "newPassword": "654321" }
```

```json
{ "code": 200, "message": "ok", "data": null }
```

| 场景 | HTTP | message |
| --- | --- | --- |
| 原密码为空 | 400 | 请输入原密码 |
| 原密码错误 | 400 | 原密码不正确 |
| 新密码少于 6 位 | 400 | 新密码至少 6 位 |
| 新旧密码相同 | 400 | 新密码不能与原密码相同 |

> 修改成功后前端会清理登录态并跳回登录页。

### 2.4 退出登录

`POST /auth/logout`

JWT 无状态，后端不保存会话，前端删除 token 即可。保留接口便于将来接入黑名单或审计。

### 6.2 创建预约

`POST /bookings`

```json
{
  "deviceId": 1,
  "slotId": 1,
  "date": "2026-10-29",
  "purpose": "模型训练"
}
```

成功返回预约详情（含联表字段），初始状态 `PENDING`。

校验规则与错误提示：

| 场景 | message |
| --- | --- |
| 未选设备 / 日期 / 时段 | 请选择设备、日期和时段 |
| 日期早于今天 | 不能预约过去的日期 |
| 超过 14 天 | 最多只能提前 14 天预约 |
| 设备不存在 | 设备不存在 |
| 设备非可用 | 该设备当前不可预约（MAINTENANCE） |
| 时段不存在 | 预约时段不存在 |
| 时段已开始 | 该时段已经开始，请选择更晚的时段 |
| 用户同时段重复 | 你在该时段已有预约，不能重复预约 |
| Redis 锁被占用 | 该时段正在被其他同学抢约，请稍后重试 |
| 设备同时段被占 | 该设备的这个时段已被预约，请选择其他时段 |

> 「设备同时段被占」由 `active_key` 唯一索引触发，并发场景下只有一条能插入成功。
> Redis 锁只是前置削峰，未启用 Redis 时会跳过锁，仍由数据库唯一索引保证正确性。

### 6.7 审批

`POST /bookings/{id}/approve`（管理员 / 教师）

通过：

```json
{ "approved": true, "remark": "审批通过" }
```

驳回：

```json
{ "approved": false, "remark": "设备当天检修，请改约" }
```

| 场景 | message |
| --- | --- |
| 预约不存在 | 预约记录不存在 |
| 已被处理 | 该预约已被处理，请刷新列表 |
| 审批自己的预约 | 不能审批自己提交的预约 |
| 时段已开始 | 该预约时段已开始，无法审批 |
| 并发处理失败 | 审批失败，请刷新后重试 |

> 审批 SQL 带 `where status = 'PENDING'`，天然防止重复审批。

## 9. 预约状态与错误码

### 9.1 状态枚举

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待审批 |
| `APPROVED` | 已通过，等待签到 / 使用 |
| `REJECTED` | 已驳回 |
| `CANCELLED` | 已取消（用户取消或超时未审批） |
| `COMPLETED` | 已完成 |
| `VIOLATED` | 违约（未签到） |

### 9.2 常见状态码

| HTTP | 含义 | 前端处理 |
| --- | --- | --- |
| 200 | 成功 | 正常渲染 |
| 400 | 参数 / 业务校验失败 | 弹出 `message` |
| 401 | 未登录或 token 过期 | 清理登录态，跳登录页 |
| 403 | 角色权限不足 | 弹出 `message` |
| 404 | 资源或接口不存在 | 弹出 `message` |
| 500 | 服务端异常 | 弹出 `message`，看后端日志 |

## 10. WebSocket 实时通知

### 10.1 连接

```text
ws://127.0.0.1:8091/ws/notifications?token=<JWT>
```

生产环境（Nginx 同源）：

```text
wss://your-domain/ws/notifications?token=<JWT>
```

- 浏览器原生 WebSocket 不能设置 `Authorization` 头，因此 token 放在查询参数
- 握手由 `JwtHandshakeInterceptor` 校验；无效 / 过期 token 返回 HTTP 401，连接失败
- 开发期 Vite 已配置 `/ws` 代理（`ws: true`）
- 一个用户可以同时建立多个连接（多标签页），消息会推送到该用户所有在线会话

### 10.2 消息格式

服务端推送 JSON 文本：

```json
{
  "type": "BOOKING_APPROVED",
  "title": "预约已通过",
  "content": "你对 视频会议终端 · 2026-10-28 08:00-10:00 的预约已通过，备注：审批通过",
  "bookingId": 22,
  "at": "2026-10-27 15:51:20"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | 事件类型，见下表 |
| `title` | string | 标题 |
| `content` | string | 正文 |
| `bookingId` | number / null | 关联预约 id；系统级消息为 null |
| `at` | string | 服务端时间 `yyyy-MM-dd HH:mm:ss` |

### 10.3 事件类型

| type | 接收方 | 触发时机 |
| --- | --- | --- |
| `CONNECTED` | 当前连接 | 握手成功，通道就绪 |
| `PONG` | 当前连接 | 客户端发送 `ping` 后回复 |
| `BOOKING_CREATED` | 申请人 | 预约提交成功 |
| `PENDING_CREATED` | 管理员 / 教师 | 有新的待审批预约 |
| `PENDING_CHANGED` | 管理员 / 教师 | 待审批队列变化（通过 / 驳回 / 取消 / 超时） |
| `BOOKING_APPROVED` | 申请人 | 审批通过 |
| `BOOKING_REJECTED` | 申请人 | 审批驳回 |
| `BOOKING_CANCELLED` | 申请人 | 用户取消或超时未审批自动取消 |
| `BOOKING_COMPLETED` | 申请人 | 已签到且时段结束，系统标记完成 |
| `BOOKING_VIOLATED` | 申请人 | 未签到且时段结束，系统判定违约 |

### 10.4 心跳

客户端每 25 秒发送纯文本：

```text
ping
```

服务端回复：

```json
{ "type": "PONG", "at": "2026-10-27 15:51:20" }
```

前端收到 `PONG` 后不再向下分发，只用于保活 / 探测半开连接。

### 10.5 推送时机与可靠性

- 所有业务推送都在 **事务提交后** 执行（`TransactionSynchronization.afterCommit`）
- 事务回滚不会发送通知
- 当前只推在线用户，不做离线补发；后续可落库站内信 + 未读数
- 推送失败只记录日志，不影响主业务
- `PENDING_CHANGED` 只用于静默刷新角标 / 队列，不进入消息中心

## 11. 缓存说明

开启 `REDIS_ENABLED=true` 后，以下接口使用 Redis 缓存；未开启时使用 Caffeine 本地缓存，接口行为一致。

| 缓存名 | 对应接口 | TTL |
| --- | --- | --- |
| `devicePage` | `GET /devices/page` | 60 秒 |
| `categories` | `GET /categories` | 5 分钟 |
| `statsOverview` | `GET /stats/overview` | 30 秒 |
| `statsStatus` | `GET /stats/status-distribution` | 60 秒 |
| `statsTop` | `GET /stats/top-devices` | 60 秒 |
| `statsCategory` | `GET /stats/device-by-category` | 5 分钟 |
| `statsTrend` | `GET /stats/booking-trend` | 60 秒 |

Redis key 形如：

失效策略：

- 设备 / 分类新增、修改、删除 → 清理设备分页、分类、相关统计缓存
- 预约创建、审批、取消、自动完成 / 违约 → 清理全部统计缓存
- 缓存清理在事务提交后执行，避免回滚造成缓存与数据库不一致
- Redis 故障时自动降级为查库，并打印限流 WARN 日志
