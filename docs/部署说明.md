# 部署说明（第三阶段）

本文覆盖两种运行方式：

1. **本地开发**：MySQL + 可选 Redis + Maven + Vite
2. **Docker Compose**：MySQL + Redis + 后端 + Nginx 前端，一键启动

---

## 1. 部署架构

```text
                    浏览器
                      │  http://127.0.0.1:8080
                      ▼
              ┌───────────────┐
              │    frontend   │  Nginx
              │  /  → dist    │
              │  /api → 8091  │
              │  /ws  → 8091  │
              └───────┬───────┘
                      │ Docker 内部网络
                      ▼
              ┌───────────────┐
              │    backend    │  Spring Boot :8091
              └──┬─────────┬──┘
                 │         │
                 ▼         ▼
          ┌──────────┐  ┌──────────┐
          │  mysql   │  │  redis   │
          │  :3306   │  │  :6379   │
          └──────────┘  └──────────┘
```

宿主机端口映射：

| 服务 | 容器端口 | 宿主机端口 | 说明 |
| --- | --- | --- | --- |
| frontend | 80 | 8080（可配置） | 统一入口 |
| backend | 8091 | 8091 | 便于直接调接口 |
| mysql | 3306 | 127.0.0.1:3307 | 避免和本机 MySQL 冲突 |
| redis | 6379 | 127.0.0.1:6380 | 避免和本机 Redis 冲突 |

## 2. Docker Compose 部署

### 2.1 前置条件

- Docker Engine 24+ / Docker Desktop
- 可访问 Docker Hub（首次构建需拉取基础镜像与依赖）
- 空闲端口：8080、8091、3307、6380

### 2.2 配置环境变量

```powershell
cd lab-booking
Copy-Item .env.example .env
```

编辑 `.env`：

```dotenv
DB_PASSWORD=please-change-me
JWT_SECRET=please-change-me-to-a-random-string-at-least-32-chars
FRONTEND_PORT=8080
```

> `.env` 已被 `.gitignore` 忽略，不会提交。
> `JWT_SECRET` 至少 32 字符，可用 `openssl rand -base64 48` 生成。

### 2.3 启动

```powershell
docker compose up -d --build
docker compose ps
```

启动顺序由健康检查保证：

```text
mysql healthy ─┐
               ├─▶ backend healthy ─▶ frontend
redis healthy ─┘
```

首次启动：

- MySQL 创建 `lab_booking` 库
- 后端执行 `db/schema.sql` 建表
- `DataInitializer` 写入演示账号、设备、预约数据

访问 <http://127.0.0.1:8080>，使用 `admin / 123456` 登录。

### 2.4 验证

```powershell
# 后端健康检查（应看到 redisEnabled=true）
curl.exe http://127.0.0.1:8091/api/health

# 前端
curl.exe -I http://127.0.0.1:8080

# Redis 中的缓存 key
docker compose exec redis redis-cli --scan --pattern "lab:cache:*"

# 后端日志（含 WebSocket 连接日志）
docker compose logs -f backend
```

浏览器打开页面后：

- 顶栏状态应为 `REALTIME`
- `/api/health` 的 `websocketOnline` 应大于 0
- 用两个账号分别登录，提交 / 审批预约应实时收到通知

### 2.5 常用运维命令

```powershell
docker compose stop                # 停止
docker compose start               # 启动
docker compose restart backend     # 重启后端
docker compose down                # 停止并删除容器（保留数据卷）
docker compose down -v             # 连数据卷一起删除
docker compose logs --tail=200 backend
docker compose exec mysql mysql -uroot -p lab_booking
```

### 2.6 数据备份与恢复

```powershell
# 备份
docker compose exec mysql sh -c "mysqldump -uroot -p\"$MYSQL_ROOT_PASSWORD\" lab_booking" > backup.sql

# 恢复
Get-Content backup.sql | docker compose exec -T mysql sh -c "mysql -uroot -p\"$MYSQL_ROOT_PASSWORD\" lab_booking"
```

Redis 仅存缓存与短期锁，不需要备份；重启后缓存自然重建。

## 3. 本地开发部署

### 3.1 后端

```powershell
cd backend
Copy-Item src\main\resources\application-local.yml.example src\main\resources\application-local.yml
# 填写 MySQL 密码与 JWT 密钥

# 可选：启用 Redis
$env:REDIS_ENABLED='true'

mvn spring-boot:run
```

### 3.2 前端

```powershell
cd frontend
npm install
npm run dev
```

开发期代理：

- `/api` → `http://127.0.0.1:8091`
- `/ws` → `ws://127.0.0.1:8091`（`ws: true`）

### 3.3 Redis 可选性

| 配置 | 缓存 | 抢约锁 | 适用场景 |
| --- | --- | --- | --- |
| `REDIS_ENABLED=false`（默认） | Caffeine 本地 | 跳过 | 单机开发、无需额外依赖 |
| `REDIS_ENABLED=true` | Redis | 启用 | 演示第三阶段、多实例部署 |

Redis 故障时：

- 缓存读写异常 → `CacheErrorHandler` 降级查库
- 加锁异常 → 返回 `NOOP_TOKEN`，由数据库唯一索引兜底
- 解锁异常 → 锁按 TTL 自动过期

## 5. Nginx 配置要点

`frontend/nginx.conf` 已包含：

```nginx
location /api/ {
    proxy_pass http://backend:8091;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

location /ws/ {
    proxy_pass http://backend:8091;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

三个关键点：

1. **SPA 回退**：刷新 `/dashboard` 不能 404
2. **WebSocket Upgrade**：缺少 `Upgrade` / `Connection` 会导致握手失败
3. **长连接超时**：`proxy_read_timeout` 要大于心跳间隔，否则连接会被反复断开

静态资源 `/assets/` 设置了 30 天强缓存，文件名带 hash，可安全长期缓存。

## 7. 常见问题

### 7.1 后端容器反复重启

```powershell
docker compose logs --tail=200 backend
```

常见原因：

- MySQL 还没就绪（等待健康检查，或调大 `start_period`）
- `DB_PASSWORD` 与 MySQL 初始化密码不一致（改密码后需 `down -v` 重新初始化）
- `JWT_SECRET` 为空

### 7.2 前端能打开但接口 502

- 确认 `backend` 容器健康：`docker compose ps`
- Nginx 中 `proxy_pass http://backend:8091` 的服务名必须是 Compose 服务名 `backend`
- 后端监听地址必须是 `0.0.0.0`，不能是 `127.0.0.1`

### 7.3 WebSocket 一直 OFFLINE

- 浏览器控制台看 WS 握手状态码
- 401：token 过期，重新登录
- 502 / 400：Nginx 未转发 `Upgrade` / `Connection`
- 连接很快断开：检查 `proxy_read_timeout` 是否小于 25 秒心跳

### 7.4 修改代码后镜像没更新

```powershell
docker compose build --no-cache backend
docker compose up -d backend
```

### 7.5 想清空演示数据重新初始化

```powershell
docker compose down -v
docker compose up -d --build
```

注意：`-v` 会删除 MySQL 与 Redis 数据卷，不可恢复。
